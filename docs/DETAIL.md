# 谷谷股 v1.24.4 · 自用小账本（dsh-gugu-stock）

## 版本号规则（用户指定，m04960）

- 版本号是 `1.x`，**每次用户要求 +1 时只递增 x**：`1.9 → 1.10 → 1.11 …`（是小数的第十位，不是 1.9 进位成 2.0）。
- **小数点前的 `1` 未经用户明确许可不得改动**，任何情况下都不要自行升到 `2.0`。
- 同步位置：`package.json` 的 `version`、`client.js` 的 `titleSuffix`、`locale/zh.json` + `locale/en.json` 的 `title` 与 `titleSuffix`、本文件首行、`README.md`。

## 面板外观（v1.16）

- **没有顶部 Intro**：设置页/侧栏面板的说明行来自 locale 的 `meta.description`，v1.9 起置为空串，面板顶部只有卡片。
- **标题两段式**：`谷谷股`（19px / 800）与 `v1.24.4 · 自用小账本`（12.5px / 500 / 次要色）共用一行基线，窗口变窄时自动换行。
把 DeepSeek 充值余额、WorkBuddy 积分和阿里云卡券余额变成三条可以回看的曲线：DSH 开着时每 15 分钟各采样一次（DS 总余额 = 充值 + 赠金；WB 积分 = 当前账号剩余积分；阿里云卡券 = 指定代金券的剩余余额，默认关闭），写进同一份 CSV；设置 → 谷谷股（或左侧栏谷谷股图标）里可以打开 CSV、立刻采样、用 Python 画折线图 / 花费柱状图。

## 数据

- 路径：`%USERPROFILE%\.dsh\data\gugu-stock\balances-v2.csv`（可用 `GUGU_STOCK_DIR` 覆盖目录）
- 编码：UTF-8 with BOM，CRLF 行尾，Excel / WPS 双击即可读写
- 表头：`时间,来源,数值`；第一列时间 `YYYY-MM-DD HH:mm:ss`（本地时区），第二列来源 `ds`（DeepSeek 余额，元）/ `wb`（WorkBuddy 积分）/ `al`（阿里云代金券剩余余额，元；旧文件里写成 `aliyun` 也照样读）/ `ut`（**累计消耗的 tokens，整数**，v1.19 起；语义是「消耗」不是「余额」，图上按每天增量画），第三列数值（最多 6 位小数）。旧表头（`时间,ds/wb,数值`）与旧的两列文件（`时间,余额`）仍能读，前者按 ds/wb 解析、后者按 `ds` 处理
- 从 Excel 粘贴的行也认 Tab 分隔（`2026/11/11 14:22<Tab>al<Tab>300`），时间支持 `/` 或 `-`、可带秒可不带
- **采样时间精确到秒**：CSV 落盘时间格式为 `YYYY-MM-DD HH:mm:ss`（带秒），界面「最近采样」也显示到秒
- **卡券使用流水表整表导入**：`node acceptance/tools/import-coupon-flow.mjs` 读取桌面的 `*-coupon_use_flow.csv`（`时间,al,余额`，斜杠日期、无表头），同一分钟内多条记录按出现顺序分配秒 `:00/:01/:02…` 全部保留，纯追加进同一个 CSV；导入后即进入 `al` 序列出图
- **WB 消耗明细整表导入（request-usage 工作簿）**：脚本 `acceptance/tools/import-wb-usage.py`（`--xlsx … --csv … [--dry-run]`）。工作簿里第二列是**那一次消费的积分**、不是余额，所以脚本以 CSV 中**最老的一条 wb 余额**为锚点倒推：锚点之前按时间降序把消费累加回去（越早余额越高），锚点之后按升序逐笔减掉；同一时间戳多笔先求和、只落一行。写盘是**纯追加** ASCII 行 `时间,wb,余额`，不动任何既有行，导入后由自动整理把新行按时间排好（v1.16）
- **只有一个 CSV，纯追加**：运行时采样**只往文件末尾追加一行**——绝不重写、不重排、不删除任何已有行。文件按时间升序（旧的在上、新的在下）；`(时间,来源)` 完全相同的记录会跳过，不产生重复，但已有的行连一个字节都不会被动
- **顺序自动整理（v1.16）**：如果别处把行挪乱了（典型是 Excel 保存时把某段搬到最顶部），插件会在**启动、每次采样之后、每次出图之前**自动把行按时间排回升序——只重排，不删行、不改编码、不改每行的原始字节格式；已经有序时是零写盘的空操作。为此界面上**没有**「整理表格」按钮，`state.lastTidyAt / lastTidyMoved / lastTidyReason` 可查它最近一次什么时候理了、挪了几行、因为什么触发
- **没有 sticky 影子表**：曾经为对抗外部旧引擎吞行加过的 `balances-v2.csv.sticky` 已彻底删除，所有数据（含用户手加行、卡券流水）都只存在于 `balances-v2.csv` 这一个表里。注意：本机若同时跑着多个 DSH 引擎，旧引擎仍可能整体重写这个 CSV——插件自身已经不再做任何删除；如需彻底避免，请只保留一个 DSH 实例
- 写入方式：采样走 append（遇 Windows 文件锁 EBUSY/EPERM/EACCES 重试 6 次）；一次性迁移/导入工具仍走临时文件 + rename，行数腰斩写前留 `.bak-shrink-*` 后备

## 采样

- 插件激活时若最新一行早于 5 分钟，立即补一次采样；此后每 15 分钟一次
- DS 余额来源：优先 `DEEPSEEK_API_KEY`（`https://api.deepseek.com/user/balance` 的 `total_balance`），否则走 DSH 已登录账号的钱包合计（充值钱包 + 赠金钱包）
- WB 积分来源：本机 `dsh-connect-workbuddy` 的 loopback 路由 `GET /plugins/dsh-connect-workbuddy/account-credits`（不带 Origin 头），取 `accounts[].credits`（数字或 `{ total }` 两种形状都认）。**多个 WB 账号时取全部可读账号之和**（v1.18.4 起；以前只取 `selected`，多号会漏算），读不出积分的账号跳过；一个都读不到才记 `lastWbError`，不影响 DS 采样。`/state` 里额外回 `wbAccounts`（`[{name,value,selected}]`）与 `wbAccountCount`，面板在 WB 卡片下写「N 个账号合计」
- Tokens 消耗来源（`ut`，v1.19）：扫 `%USERPROFILE%\.dsh\sessions\*\*\session.v4.jsonl.zstd`（**含已归档会话**——归档只是从列表里隐藏，日志还在原处），把这些日志里 `assistant/message` 的 `data.usage` 按 `(turn, step)` 去重后加总（`inputTokens + outputTokens + cacheReadTokens + cacheWriteTokens`），得到**整机累计 tokens** 写一行 `ut`。日志是**多帧 zstd 追加**的，Node 的 `zstdDecompressSync` 一次只吐首帧，所以 `lib/tokens.js` 先扫帧魔数 `28 b5 2f fd` 再逐帧解压拼接；每个会话的 total 按 `{size, mtimeMs}` 缓存在 `.token-cache.json`，全机 139 个会话首次约 1.8 秒、之后约 14 毫秒，不需要任何凭据或手动输入
- 各路采样并行取数，但**写 CSV 串行**（读 → 合并 → 原子写 排队），避免后写覆盖先写
- 余额两条路都失败时不写脏数据，只在界面上报原因；`ut` 不依赖凭据，余额全挂时它照样落一行，所以 `/sample` 的 `ok` 以「有没有写进任何一行」为准

## 设置页

设置侧边栏新增「谷谷股」页签（id `gugu-stock`，order 30），包含：

**主区域只留三个按钮**：`立即采样`、`生成 · 余额折线图`、`生成 · 花费柱状图`；其余按钮与设置项全部收进下面的「配置」块。

**配置块默认收起**（标题行右侧一个「配置 / 收起」按钮），展开状态记在 `localStorage` 的 `gugu-stock.configOpen`，刷新页面后保持上次的样子。展开后分四个板块，板块标题 **15px / 700 / 主文字色**（比正文大一号），序号 `①②③④` 单独一个 `span`、与标题之间靠 `gap: 8px` 分隔：

1. **① 打开文件** —— 「打开 csv 文件」：交给系统默认程序（Windows 上 `cmd /d /c start "" <path>`，失败回退 `rundll32 url.dll,FileProtocolHandler`），文件本身可读可写。下方固定一行说明：**「在谷谷股数据搬迁时，仅需搬迁此 csv 文件即可。」**
2. **② 数据源配置**
   - 四个开关（默认 读取DS余额=开 / 读取WB积分=开 / 读取阿里云卡券=**关** / 读取 Tokens 消耗=开）：关掉的来源既不采样、也不画线、顶部也不显示对应数值块
   - 打开「读取WB积分」后，开关下方出现一行提示：**「开启后，正在自动读取 dsh-connect-workbuddy 的数据作为 WB 积分数据（未安装该插件时不会有数据）。」**
   - 阿里云卡券需要四个输入框：`阿里云子账号`、`阿里云卡券编号`、`阿里云 AccessKey ID`、`阿里云 AccessKey Secret`。**这整块只在「读取阿里云卡券」打开时渲染**（默认关闭，所以默认看不到它）；关闭开关**不会清除**已经填过/存过的内容，重新打开即恢复。说明文案（RAM 控制台建只读子账号 → 授予 `AliyunBSSReadOnlyAccess` → 建 AccessKey → 填到上方，密钥只用于写入、不回显）排在**「测试连接」按钮与测试结果的上方**
   - **默认全部为空**（不预填任何隐私信息）；ID/Secret 走密码框，提交后只写进 DSH 凭据库（`~/.dsh/.credentials.yaml` 的 `ALIYUN_ACCESS_KEY_ID` / `ALIYUN_ACCESS_KEY_SECRET`），**不写进 `settings.json`、接口也不回显**，页面只显示「已保存」与掩码
   - 另有一个「测试连接」按钮：立刻用当前配置查一次券，成功显示余额、失败显示原因（未填全 / 无权限 / 找不到券）
3. **③ 缩放** —— 四个数值：`DS 100`、`WB 3.25`、`阿里云卡券 12.5` 是显示高度百分比；`日Tokens 消耗` **不是百分比，而是 divisor**（多少 tokens 折算成纵轴 1 格），默认 **12500000**（每 1250 万 tokens 记 1 格）。每项是一个 `number` 输入框 + `▲▼` 两个按钮，**每点一次 ±0.25**（ut 为 ±100000），百分比范围 0.05~400、ut 范围 1000~1000000000。改完立刻写入 `settings.json` 落盘，刷新页面、插件或 DSH 重启后仍是上次的值。该板块末尾有一行解释 ut 含义的说明
4. **④ 采样间隔** —— 分钟数，默认 15


- 「日期区间」两个 `date` 输入框 + 「重置为最近 60 天」：**不放在配置块里，常驻在三个主按钮的正上方**（折叠配置块也照样可见），直接决定两个生成按钮画哪一段；为空时后端回退最近 60 天
- 「图表主题」明 / 暗 / 自动三选一（默认自动，在配置块内）：只影响生成的图，不改插件页面配色。`自动` 由浏览器按 `prefers-color-scheme` 解析成明或暗后再发给 Host，因此同一台机器在不同系统外观下出的图不同；选择同样落盘到 `settings.json`。暗色主题下 WB 一律比 DS 更深（折线、节点、柱子、数字都按这个方向配色）
- 「颜色来源」增减 / 数据源 二选一（默认「增减」，在配置块内，主题行下面）：同时影响**折线图的线段着色与图例**和**柱状图的柱色、花纹与图例**。选「增减」时折线按每段涨跌上色（升红 `#d64545`、降绿 `#1a9c5b`、平灰 `#c8c8c8`；DS 与阿里云都按此规则，WB 沿用主题浅红/浅绿/浅灰变体），柱状图按区间内日花费 min→纯绿 `#1a9c5b`、中点→纯黄 `#f0c400`、max→纯红 `#d64545`（花得越多越红；DS/阿里云走纯热力，阿里云不再混浅色），并用**三种花纹区分来源**——DS 纯色无花纹 / WB 斜线 `///` / 阿里云圆点 `...`（花纹用文字色描边），图例三根小柱带对应花纹。选「数据源」时三条折线各自用固定色——DS 蓝 `#2563eb/#2563c9`、WB 绿 `#7bc9a0`、阿里云橙红 `#e8461a`（暗色主题 `#ff6b3d`），柱状图三根柱子也各用数据源固定色、不加花纹；图例都改成三条彩色线段/三根彩色小柱，分别标 `DS 花费（元）/ DS 余额`、`WB 花费（积分 N%）/ WB 积分`、`阿里云卡券花费/阿里云卡券`。节点/数字颜色不随这个选项变化（始终按数据源着色）；选择落盘到 `settings.json`，刷新/重启后保留
- 花费定义：当天余额**下降幅度之和**（10→9→8→7→12→11→10 记 5 元，充值不抵消）；「增减」模式下柱色按区间内日花费 min→纯绿 `#1a9c5b`、中点→纯黄 `#f0c400`、max→纯红 `#d64545` 两段线性过渡（花得越多越红）（0 值柱不标数字），并用三种花纹区分数据源：DS 纯色 / WB `///` / 阿里云 `...`
- 有 WB 数据时每天把各数据源的柱子**等宽并排**（不再降低 WB 宽度，DS / WB / 阿里云一律同宽）；明色主题「增减」模式 WB 混白变浅、暗色主题混近黑变深；图例是三根等宽小柱子（「增减」模式颜色相同但带 `///`/`...` 花纹区分，「数据源」模式下分别为蓝/绿/橙红）；**柱顶数字按类目取色**——DS 蓝、WB 绿、阿里云橙红（暗色主题用各自的亮版），一眼看出这个数字属于哪条序列（v1.18 起）；轴顶留一条空白带放手绘图例，最高那根柱子和它的数字不会被图例压住

- 「保存到桌面」：把图表卡片里显示的那张 PNG 复制到桌面，文件名 `谷谷股_折线图_YYYYMMDDhhmmss.png` 或 `谷谷股_柱状图_YYYYMMDDhhmmss.png`（本地时间）；不重跑 Python，所以和卡片里看到的一模一样；同名自动加 `-2`/`-3`；没生成过图时提示先点生成。桌面目录按 `GUGU_DESKTOP_DIR` → `~/Desktop` → `~/OneDrive/Desktop` → `~/桌面` 顺序取第一个存在的

## 纵轴不留零下空白带（v1.23.5）

- DS 余额常是 `-0.011989` 这种浮点噪声。`axis_bounds()` 以前一律按 10 向下取整，于是纵轴从 -10 起、底部空出一整格（用户 m15687）。
- 现在：`lo < 0` 且最低点在 `-1` 以内时视为 0，纵轴从 0 起；真的负余额（`-5.2`）仍取整到 -10，数据看得见。

## 折线图规格

- 只画最近 60 个「有数据」的日期；不足 60 天就只画现有日期。**只画开关打开的来源**（三路全关时后端直接报 `no_source`，不生成空白图）；图例、节点、数字都随开关增减
- 每个 CSV 行都是一个折线节点；同一天内多条记录在本日的水平区间内均分
- 三条序列同轴画，各自按面板上的「缩放」百分比折算（`y = 数值 × 百分比 / 100`，默认 DS 100%、WB 3.25%、阿里云 12.5%），标签仍取原始值；DS 蓝 `#2563eb`、WB 浅绿、阿里云橙红 `#e8461a`（暗色主题 `#ff6b3d`）；明色主题 WB 用更浅的色板、暗色主题用更深的色板（相邻节点一律连线，只有「没有节点」才意味着缺数据）
- 只有每天最后一个节点画圆点并标注当天最终余额（**标注四舍五入到整数**；CSV、纵轴、插件页面数字仍是真实值）
- 若窗口里只有一天数据：改为标首、末两个节点（用户能看出这段时间余额从哪走到哪）
- **相邻两个节点都有有效数值就一定连线**，不存在「跨空档不画线」的特例：横轴上跨午夜的相邻点可能相距 1 格以上，仍然照常用线段连接；数据缺口靠「没有节点」本身表达，不靠删掉连线
- 相邻节点比较：下降=绿 `#1a9c5b`，上升=红 `#d64545`，持平=浅灰 `#c8c8c8`
- 横轴每天占等宽 1 格（=24 小时），节点按真实时钟落位：12:00 落在半格、23:30 落在接近格末；每个日期的开头与结尾各一条竖分隔线，标签**每个月只在最左那天写 `MM-DD`、同月其余日期只写 `DD`**（v1.10 起，跨月时新月份的第一天重新带上 `MM-DD`）；横轴范围固定从第一天 0 点到最后一天 24 点，首日与末日都完整占满一整格、两端都不裁（这条 8 分片裁切机制已按用户要求删除），日期标签落在每格正中；**横轴一天一格，任何情况下都不折叠**（连续几天余额不变时日期照样逐天排列，标签仍按「每月首个写 `MM-DD`、其余写 `DD`」逐个写出）；**DS 的内容恒盖在另外两条之上**（折线 3 > 2 > 1、节点 5.4 > 4 > 3.6、数字 6 > 5 > 4.6），两者重叠时看到的一定是 DS 的蓝点与蓝字；图上所有数字的底衬都是贴合字形的半透明描边（不是整块矩形，不会挡住后面的线与柱子）；折线图图例是几个小圆点（DS 蓝 / WB 浅绿 / 阿里云橙红，按打开的开关显示），与节点颜色一致；WB 折线每天的最终节点都要标数字，相邻标注贴得太近时往下错开一档，不做省略；纵轴取 10 的倍数包住最小/最大值、网格线每 10 一条（v1.17 由 25 改为 10，如 67→[60,70]，182→[180,190]）；若数据跨度不足 10（例如全平的 100.0），轴域上下各外扩 10（100→[90,110]），曲线不会贴在轴上
- 只有每日最终节点、整张图最左与最右两个节点、以及窗口内最高点与最低点画圆点并标注数值（四舍五入到整数）；最低点的数字放在点下方，其余行只是折线节点

## HTTP 接口（前缀 `/gugu-stock/api`）

## Tokens 消耗数据源（v1.19）

第四个数据源，用户 m09984 / m09998 / m10385 / m11760 定的规则：

1. **数据**：DSH 所有会话（**包括已归档**）所有对话消耗的 tokens 总和，每 15 分钟采样一次，写进同一个 CSV 的 `ut` 行，值是**累计整数**（不做任何单位换算、不需要调用方手输）。
2. **折线图**：`ut` 不画折线、也不画节点（v1.20.4，用户 m12288），只把**曲线下方到 0 轴之间的区域**涂成半透明紫（`#7c3aed` / `#a78bfa`，alpha 0.30）。它表示消耗量，涨红跌绿对消耗没有意义，所以两种颜色模式下都是紫色。只有当天最后一个采样点带数字。
3. **每天 00:00 一定是 0**：日消耗 = 当天某个采样点的累计值 − **前一天最后一个**采样点的累计值；图表把每天的第一个点固定成 `00:00:00 / 0`，之后的每个采样点画「截至该时刻的当天累计消耗」，第二天再从 0 起。整表第一条 `ut` 之前没有基线，所以**第一天从 0 起算**（避免把历史总量当成某一天的消耗）。
   - **没有数据的日期也要画**（v1.19 起）：ut 的线与柱覆盖整个时间窗，某天没有 `ut` 采样（或早于 v1.19 的日期）就按 `0` 画——线贴着 0 轴走、柱是 0 高、柱顶写 `0`；实现是 `ut_day_info()` 对缺日返回 `{"value": 0.0, "points": [("00:00:00", 0.0)]}`，`tokens_days`/`ut_days` 直接用整个 `window`。
4. **数字：只有 ut（紫色）用粗粒度中文单位**（v1.20.7，用户 m12655）：`732万`写作 `7百万`、`4876万`写作 `4千万`、`1亿1578万`写作 `1亿1千万`、`554万`写作 `5百万`、`1376`写作 `1千`、`167`写作 `1百`、`67`写作 `67`（一百以下原样）。实现是 `token_label()` → `coarse_label()`。**DS / WB / 阿里云三条序列是纯阿拉伯数字**（`label_text()`：四舍五入到整数，`1008.40 → 1008`），面板数字又有自己的规则（`client.js` 的 `fmtCoarse`）——三套互不影响。只有每天最后一个采样点带数字（其余点只在线上）。**数字位置**（v1.20.6，用户 m12544）：ut 的数字不画在图里，统一放在**横轴下方、日期标签上方**，每个日期正中间一个紫色数值；相邻两个上下错开两档（`levels = (-4, -15)`），因为「2亿1千万」这种两段单位比一个日期格还宽。实现是 `ut_axis_items()` + `draw_ut_axis_labels()`，同时把横轴刻度 `pad` 加到 23、画布加高到 6.15in、`tight_layout(rect=(0, 0.10, 1, 1))` 给这条带留位。
5. **柱状图**：每天一根**半透明紫色**柱（alpha 0.30），宽度**覆盖整天**、居中，`zorder` 垫在 DS/WB/阿里云柱**后面**（v1.20.4）；高度 = 当天消耗 / 缩放，柱顶数字同样用粗粒度中文单位（v1.20.5，`0` 也写 `0`）。
6. **缩放**：tokens 是消耗量，用百分比没法看，所以 `ut` 的缩放是「**多少 tokens 折 1 纵轴单位（divisor）**」，默认 **5,000,000**（500 万/格），区间 `[1000, 1e9]`、`▲▼` 每次 ±100,000。宿主 `clampScale('ut', …)`、`/state` 的 `scaleSteps.ut` / `scaleRanges.ut`、`utDivisor`、client 的 `UT_RANGE_DEFAULT`、`gugu_chart.py` 的 `sanitize_scale_for('ut', …)` 五处口径一致。
7. 面板：第四个数据源开关「读取 Tokens 消耗」（默认开）、第四个缩放行、`Tokens 消耗` 数值卡（`utCount` 记条数）。
8. 无 shell 的 Agent（用户 m10349）：`gugu_stock` 工具支持 `action=chart, kind=both`，一次调用同时出三张图并返回 `charts[].chartPath`，不需要任何 bash 命令。
9. **ut 行是增量（v1.21.4，用户 m13230）**：CSV 里每一条 `ut` 记录不再是「历史累计 tokens」，而是「这一次检测比上一次检测多了多少 tokens」。采样时 `delta = max(0, 本次累计 − 上一次累计)`，上一次累计存在 `settings.json` 的 `utBaseline` 里（每写成功一行就推进一次；同一分钟被去重跳过时不推进，留给下一次补上）。下游一律用加法：某天消耗 = 当天所有 `ut` 行相加，总消耗 = 全表相加。好处是每行都小、永远非负、不需要任何平移值，也不会因为会话日志被删/被新增而出现倒挂。这张表里历史行在 v1.22.0 迁移时已按时间顺序换成差值（总和不变）。

10. **消失的会话继续计入（v1.21.4，用户 m13145）**：token 总量是「所有会话日志的累计之和」，如果某个会话被删除（或日志变得读不出来），它的消耗不该从总量里消失——否则 ut 会假下降、图上出现倒挂。做法：`.token-cache.json` 按 `<workspace>/<session>` 记下每个会话最后一次的累计值；每次采样时**磁盘上找不到的会话按记下的值继续计入**。缓存文件删掉才会忘掉这些会话。同一条会话的日志被截断/重写时也取 `max(本次解析值, 上次记下的值)`。状态里多了 `utRemembered`（记得几个已消失会话）与 `utRememberedTokens`（它们贡献多少）。

## 多账号加总（v1.18.4）

`dsh-connect-workbuddy` 的 `account-credits` 路由回的是一个 `accounts` 数组。旧代码只挑 `selected === true`（没有就挑第一个）那条，所以一个 DSH 里挂了两个 WB 号时，CSV 里的 `wb` 只反映其中一个号。

现在改成**全部可读账号相加**：

- 每个账号的 `credits` 支持数字与 `{ total }` 两种形状，两种都算可读；
- 读不出积分的账号（`credits` 为 `null` / 缺失）直接跳过，不当作 0 混进加总——`numeric(null)` 会返回 0，这是这次特意挡掉的坑；
- 至少一个可读才算成功，全部读不到才报 `wb_sample_failed`；
- `/state` 多回 `wbAccounts`（`[{name, value, selected}]`）与 `wbAccountCount`，面板的 WB 卡片下面在账号数大于 1 时显示「2 个账号合计 · 2026-11-23 01:20:00」，只有一个号时仍然只显示时间。

CSV 格式不变：仍然是一行 `时间,wb,合计值`，加总明细只在 `/state` 里，不写进表。

## 多开 DSH 时基线共用（v1.23.1）

`utBaseline` 每次采样前都从 `settings.json` 重新读一遍，和内存里的取较大值再算差值。
原因：每个 DSH 窗口是独立进程、各有内存 state，只信内存会让同一段消耗被反复记成增量
（真机上出现过「日 Tokens 51 亿」）。基线只写本地 `settings.json`，不进 CSV。

同一个原因还带来第二处保护：定时采样前先看磁盘上该数据源最近一条的时间，10 分钟内
已经采过就跳过不写（`trigger !== 'manual'` 时才生效）。手动「立即采样」永远真写一行。
否则 16 个窗口各自的 15 分钟定时器会把同一段时间写成十几行。

## 一张表装下全部数据（v1.22.0）

- CSV 的表头之上多一行 `#gugu {"version":1,...}`，里面是面板的全部视觉设置：`theme`、`colorMode`、`sources`、`scales`（含 `wbPercent`）。
- 采样只追加数据行，从不动这一行；改设置时用 `writeMetaLine()` 只替换那一行，表头与所有数据行原样保留。
- 启动时先读表里的设置（优先于 `settings.json`）；没有就把当前设置补写进去，所以老用户升级后第一件事就是这行出现。
- 出图脚本 `scripts/gugu_chart.py` 也优先读表里那一行，读不到才退回 `settings.json`，最后才是内置默认。
- 不写进表里的只有两样：`utBaseline`（本机 token 累计基线，换机必须重来）与 `.token-cache.json`（会话日志的派生缓存）。
- 设置面板「① 打开文件」右侧新增「导入 csv 文件」：选一张表 → 整份替换数据 → 表里的设置一起生效 → token 基线归零。导入前会先把旧表备份成 `balances-v2.csv.bak-before-import-<ts>`。

## 设置面板排版重做（v1.24.4）

- **板块标题放大**：`S.configGroupTitle` 从 12px / 次要色提到 **15px / 700 / 主文字色**，四个板块标题一眼能和正文分开。
- **序号与标题分开**：`①②③④` 不再是拼在字符串里的 `'① 打开文件'`，而是单独的 `span`（`S.configGroupIndex`），两段之间用 flex `gap: 8px` 撑开——比在字符串里塞空格可靠，不受字体宽度影响。
- **阿里云整块条件渲染**：四个输入框、已保存提示、说明文案、「测试连接」按钮与结果，只在「读取阿里云卡券」打开时出现。关掉只是不渲染，`aliyunForm` 是独立 state，没有任何代码在关闭时清空它，重新打开原样恢复。
- **说明文案上移**：阿里云那段落（RAM 只读子账号 → `AliyunBSSReadOnlyAccess` → AccessKey → 填到上方，密钥只写入不回显）从板块末尾移到「测试连接」与结果**上方**，先读规则再点按钮。
- **新增两行解释**：①板块下「在谷谷股数据搬迁时，仅需搬迁此 csv 文件即可。」；②板块 WB 开关下「正在自动读取 dsh-connect-workbuddy 的数据作为 WB 积分数据（未安装该插件时不会有数据）」。
- **ut 默认值 12500000**：`日Tokens 消耗` 的 divisor 从 5000000 提到 **12500000**（每 1250 万 tokens 记 1 格），板块末尾补一行说明它是 divisor 而不是百分比、数值越小柱子越高。三处同步：`client.js` / `index.js` 的 `SCALES_DEFAULT`、`scripts/gugu_chart.py` 的 `SCALE_DEFAULTS`，以及用于兜底的 `skills/gugu-stock-charts/scripts/gugu-charts.sh`。
